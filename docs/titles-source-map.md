# 学术资历查询源地图（Academic Credentials Source Map）

> 用途：给 agent 提供"某学者是否有某头衔 / 某资历 / 某背景"的 **web fetch 方向指引**（不是 CLI 功能）。
> 定位：**§0.5 是通用方法论**（按信息类型动态选源，覆盖职称/Fellow/编委/会议主席/海外经历等一切非 API 信息）；**§1/§3 是其已知实例表**（中文头衔、国际头衔的具体入口）。
> 原则：**先锁人（学术 ID），再验资历（对应源）**；多源交叉，标注置信度；以官方为准。
> 更新：2026-08-14（新增 §0.5 通用方法论；名单逐年动态，使用前确认最新年份）

---

## 0. 使用流程（agent 必须遵循）

```
① 锁定学者身份（避免同名误判——头衔查错人的最常见原因）
   paper collect author "<姓名>" --sources openalex,ss --persist
   paper author profile <author-id>
   → 确认机构/研究方向/代表作与目标学者一致
② 判断要查的信息类型（见 §0.5.2 决策表）→ 按类型选源
③ 到对应源按"姓名 + 单位"核验（官方源优先，见 §0.5.3 query 技巧）
④ 交叉验证（见 §2）：至少两个独立来源一致才下结论
⑤ 输出：身份 + 头衔 + 来源链（URL）+ 置信度（确认/疑似/存疑）
```

## 0.5 通用学术资历查询方法论（非 API 信息总纲）

> **适用对象**：职称、Fellow、期刊编委/主编、会议主席、海外经历、教育背景、任职历史等——**一切不在 11 个学术 API 结构化字段里的学者属性**。
> **为什么需要这套方法论**：这类信息**没有统一数据源**，且随问题变化（这次查杰青→中科院/工程院源；下次查海外经历→又得换源）。因此方法论**不写死名单**，而是教 agent 按"信息类型 → 源策略 → query 构造"动态决策。CLI 永远不假装提供这些（§11.3 边界原则）。

### 0.5.1 核心原则（与 §0 相同的五步，但强调"选源"）

**先锁人 → 判断信息类型 → 按类型选源 → 交叉验证 → 标注置信度**。锁人永远是第一步（头衔查错人的最常见原因是同名误配，见 §2.3）。

### 0.5.2 信息类型 × 源策略 决策表（核心）

把"要查什么"归类，决定去哪里找。**同一类问题用同一套源策略，换人不用换方法**：

| 类型 | 典型问题 | 源策略 | 统一名录？ | 可靠度 |
|---|---|---|---|---|
| **A. 官方名录类** | 院士、杰青、长江、IEEE/ACM Fellow、各类奖项 | 官方名录/官网名单页（§1、§3 是实例） | ✅ 有 | 高（首选）|
| **B. 机构任职类** | 职称（教授/讲席/研究员）、院长/系主任、实验室主任 | 高校/院所**官网师资页**、学者个人主页、机构 news | ❌ 无统一库 | 中高（单位页权威）|
| **C. 学术活动角色类** | 期刊主编/编委/副主编、会议 General/PC/Area Chair | 期刊官网 **editorial board** 页、会议官网 **committees** 页、DBLP（偶有）| ❌ 无聚合 | 中（以期刊/会议官网为准）|
| **D. 个人履历类** | 海外工作/留学经历、教育背景、历任单位、师承关系 | 个人主页 / CV / 机构 profile / LinkedIn / 维基 | ❌ 非结构化 | 中（以本人 CV/官方页为准）|

> **选源优先级**：官方名录（A）> 单位官网（B）> 活动官网（C）> 个人页/第三方（D）。前面查不到才降级，绝不以低可靠度源代替高可靠度源下结论。

### 0.5.3 搜索 query 构造技巧（agent 联网的核心优势）

既然没有统一库，**搜索 query 的灵活性就是决定成败的关键**。通用模板：

```
# 中文名 + 单位 + 头衔词（防同名误配，头衔词按类型换）
"<中文名>" "<单位>" 院士|杰青|长江学者|IEEE Fellow|教授
"<中文名>" "<单位>" 院长|系主任|实验室主任        # B 类
"<中文名>" 主编|编委  "<期刊名>"                  # C 类期刊
"<会议名>" 主席|program chair|general chair "<姓名英文>"  # C 类会议

# 英文名 + 单位 + title
"<English Name>" "<University>" professor|chair|fellow|dean
"<English Name>" editor-in-chief|associate editor "<Journal>"
"<English Name>" general chair|program chair "<Conference>"

# 履历类（D）——换关键词即可覆盖"海外经历"等新问题
"<中文名>" 海外|留学|访问学者|博士后|工作经历
"<English Name>" education|career|research history|PhD|postdoc

# 限定官方域名（优先命中权威源）
site:edu.cn "<中文名>" 院士|杰青        # 国内高校
site:ieee.org "<Name>" fellow            # IEEE 官方
site:acm.org "<Name>" fellow             # ACM 官方
site:elsevier.com "<Name>" editor        # 期刊方
```

**技巧要点**：
1. **先带单位搜**——同名防误配的第一道闸（§2.3 同源）
2. **头衔词随类型换**——同一套模板，换词即覆盖新问题（用户预期"下次换问题"的场景）
3. **官方域名 site: 限定**——A/C 类快速直达权威页
4. **名字变体**：中文名、拼音全名、缩写（J. Yang / Jian Yang / Yang Jian）都试
5. **查不到 ≠ 没有**——先换 query（变体/加单位/去引号），再下"未获取"结论

### 0.5.4 源不确定 / 无统一名录时的处理（B/C/D 类常见）

| 情况 | 处理 |
|---|---|
| 单位官网查不到此人 | 换单位全称/英文名/历史单位再搜；仍无 → 标"未获取"（不猜测）|
| 会议主席名单只挂在会议官网（一年就换）| 以**当年会议官网** committees 页为准；DBLP 只作线索不作证据 |
| 期刊编委页随时更新 | 标注**查询日期**；"曾任编委"类历史信息难考证，标存疑 |
| 个人主页/CV 与第三方（LinkedIn/维基）矛盾 | 以**本人官方 CV/机构页**为主，第三方作佐证；矛盾时标存疑 |
| 头衔年份查不到 | 标注"年份未获取"，头衔本身有官方证据仍可"确认" |

### 0.5.5 各类别查询源速查（具体入口）

| 类别 | 首选源 | 次选 | 不推荐（仅参考）|
|---|---|---|---|
| 职称/任职（B）| 单位官网师资页 / 个人主页 | 机构 news / 学术数据库 affiliation 变化 | 自媒体 |
| IEEE Fellow（A）| IEEE Fellows Directory（ieee.org）| 个人主页自述（须回官方）| 百度百科 |
| ACM/AAAS Fellow（A）| awards.acm.org / aaas.org | 同上 | 同上 |
| 期刊主编/编委（C）| 期刊官网 Editorial Board 页 | DBLP 编辑记录（线索）| 期刊聚合站 |
| 会议主席（C）| 当年会议官网 Committees | DBLP（偶有 chair 标注）| 会议聚合站 |
| 海外经历/教育背景（D）| 本人 CV / 机构 profile | LinkedIn / 维基（佐证）| 新闻采访 |

## 1. 中国主流学术头衔 → 查询源（§0.5 类型 A 的实例）

### 1.1 两院院士（强公开，首选可查）

| 项 | 内容 |
|---|---|
| 主管部门 | 中国科学院学部 / 中国工程院 |
| **官方入口** | 中科院院士馆：`https://casad.cas.cn/yszx/` ；工程院院士馆：`https://www.cae.cn/cae/html/main/col48/index.html` |
| 查询方式 | 院士馆支持按姓名/学部/年份检索；每院士有个人页（当选年份/单位/方向）|
| 时效边界 | 完整公开，含历史全部院士（含外籍院士）|
| 备选 | 各高校官网"两院院士"介绍页；媒体（仅快速参考）|

### 1.2 杰青 / 优青（国家杰出/优秀青年科学基金）

| 项 | 内容 |
|---|---|
| 主管部门 | 国家自然科学基金委（NSFC）|
| **官方入口** | 科学基金网络信息系统：`https://www.fundamentalresearch.org.cn`（旧 `isisn.nsfc.gov.cn`）|
| 查询方式 | 系统登录后"查询与统计 → 项目信息查询 → 批准项目综合查询"（**需申请人/依托单位账号**）|
| 时效边界 | **2024 年起不公布完整名单**；2023 及以前官网有年度"建议资助项目申请人名单"通告（新闻页，可搜"国家杰出青年科学基金 建议资助 名单 年份"）|
| 备选 | 时代学者 `sdxz2050.com`、科奖中心（微信）、各高校喜报——**第三方汇总不完整，须二次核实** |
| 强证据技巧 | 论文致谢中的 **NSFC 资助号**（如 "supported by NSFC Grant No. 62xxxxxx"）——杰出青年基金有特定项目号段，与基金委系统对上即强证据 |

### 1.3 长江学者（教育部"长江学者奖励计划"）

| 项 | 内容 |
|---|---|
| 主管部门 | 教育部 |
| **官方入口** | 教育部官网 `http://www.moe.gov.cn/`（搜索"长江学者奖励计划"）|
| 查询方式 | 每年公示/公布名单（特聘教授、青年学者）为新闻通告，**无统一查询库** |
| 时效边界 | 按年查公示新闻；2022 年后规则调整（从"申报制"改为"认定制"）|
| 备选 | 高校官网"长江学者"师资介绍页（单位级，较可靠）；青塔人才/软科汇总（参考）|

### 1.4 万人计划 / 青年拔尖（国家高层次人才特殊支持计划）

| 项 | 内容 |
|---|---|
| 主管部门 | 中组部牵头，教育部/科技部等执行 |
| **官方入口** | 各主管部门公示文件（教育部/科技部官网搜索计划名称）|
| 查询方式 | 无统一公开库，按批次的公示名单（新闻）|
| 时效边界 | 分批公布（批次年份）|
| 备选 | 高校官网师资介绍；第三方汇总（标注核实）|

### 1.5 海外高层次人才引进计划（原"千人计划"）

| 项 | 内容 |
|---|---|
| 主管部门 | 中组部 |
| **官方入口** | 已并入国家高层次人才体系，无独立公开查询库 |
| 查询方式 | 基本靠高校官网"国家高层次人才"介绍页 |
| 时效边界 | 公开信息少，最难点 |

## 2. 交叉验证方法（核心）

**为什么必须交叉**：单一来源可能是同名误配、名单抄错、过期信息。交叉验证 = 两个以上**独立来源**互相印证。

### 2.1 证据强度分级

| 级别 | 证据 | 示例 |
|---|---|---|
| **强证据** | 官方名录直接命中 + 独立佐证一致 | 中科院院士馆命中 + 高校官网"院士"介绍页一致 |
| **强证据** | 论文致谢 NSFC 资助号 ↔ 基金委系统项目号 | "Grant No. 62xxxxxx" 与系统项目对上 |
| **中证据** | 单官方源命中 | 仅院士馆一条 |
| **弱证据** | 第三方汇总/媒体喜报 | 青塔/时代学者/公众号（需二次核实）|

### 2.2 交叉维度（至少取 2 个）

1. **官方源 × 第三方**：院士馆 ↔ 高校官网师资页（两者独立维护）
2. **官方源 × 高校新闻**：教育部长江学者名单 ↔ 学校官宣喜报（时间、姓名、单位对照）
3. **头衔年份 × 论文时间线**：院士当选年 ↔ 该年后的代表作/合作变化吻合
4. **头衔单位 × 论文署名单位**：杰青归属单位 ↔ OpenAlex 上作者最新机构一致
5. **资助号 × 基金委系统**（杰青/优青专属）：论文致谢基金号 ↔ 系统项目详情

### 2.3 同名防误配（必须先做）

```
同一姓名（如 "Wang Wei"）可能对应多个人：
1. 用 OpenAlex/S2 作者 ID 锁人（机构/方向/代表作比对）
2. 头衔查询必须带"单位"（如 "杰青 王晓伟 北京大学"）
3. 两个不同单位的同名者 → 分别核验，绝不混用
```

### 2.4 结论标注规则

| 情况 | 标注 |
|---|---|
| 官方源命中 + ≥1 个独立佐证 | **确认**（附来源链）|
| 仅单官方源命中 | **疑似**（建议补充佐证）|
| 官方源查不到 + 第三方有 | **存疑**（不采信，标注需人工核实）|
| 2024 后杰青类无公开名单 | **无法验证**（说明渠道限制，不猜测）|

## 4. 时效与免责

- 名单逐年动态（每年新增一批），**使用前确认最新年份**
- 以官方源为准；第三方汇总（青塔/时代学者/科奖中心/公众号）仅作**快速参考**，结论必须回官方核实
- 本表为方向指引，不替代官方数据；不确定时按 §2.4 标注"无法验证"
