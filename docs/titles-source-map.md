# 学术资历查询源地图（Academic Credentials Source Map）

> 用途：给 agent 提供"某学者是否有某头衔 / 某资历 / 某背景"的 **web fetch 方向指引**（不是 CLI 功能）。
> 定位：**§0.5 是通用方法论**（按信息类型动态选源，覆盖职称/Fellow/编委/会议主席/海外经历等一切非 API 信息）；**§1/§3 是其已知实例表**（中文头衔、国际头衔的具体入口）。
> 原则：**先锁人（学术 ID），再验资历（对应源）**；多源交叉，标注置信度；以官方为准。
> 更新：2026-08-14（新增 §0.5 通用方法论；名单逐年动态，使用前确认最新年份）

---

## 0. 使用流程（agent 必须遵循）

```
① 锁定学者身份（避免同名误判——头衔查错人的最常见原因）
   paper collect author "<姓名>" --sources openalex,ss --persist
   paper author profile <author-id>
   → 确认机构/研究方向/代表作与目标学者一致
② 判断要查的信息类型（见 §0.5.2 决策表）→ 按类型选源
③ 到对应源按"姓名 + 单位"核验（官方源优先，见 §0.5.3 query 技巧）
④ 交叉验证（见 §2）：至少两个独立来源一致才下结论
⑤ 输出：身份 + 头衔 + 来源链（URL）+ 置信度（confirmed/likely/not_found_after_search/indeterminate，见 §0.5.5）
```

## 0.5 通用学术资历查询方法论（非 API 信息总纲）

> **适用对象**：职称、Fellow、期刊编委/主编、会议主席、海外经历、教育背景、任职历史等——**一切不在 11 个学术 API 结构化字段里的学者属性**。
> **为什么需要这套方法论**：这类信息**没有统一数据源**，且随问题变化（这次查杰青→中科院/工程院源；下次查海外经历→又得换源）。因此方法论**不写死名单**，而是教 agent 按"声明 → 责任主体 → 证据"动态决策。CLI 永远不假装提供这些（§11.3 边界原则）。
> **评审记录**：2026-08-14 经 kimi-k3-256k 与 codex（gpt-5.6-sol）双模型评审后重写——核心骨架（类型驱动选源）保留，补齐身份消歧、时间语义、证据规程、产出 schema 四块。

### 0.5.1 核心原则

**给一条学者资历下结论 = 回答四个问题**：
1. **是这个人吗？**（身份消歧，见 0.5.2）
2. **这个声明由谁负责发布？**（责任主体匹配，见 0.5.3）
3. **什么时间成立？**（时间语义，见 0.5.4）
4. **证据够不够、互相独立吗？**（证据规程，见 0.5.5）

不解决这四个问题，产出就是"高置信度的错人、过期头衔、角色升级错误"（双评审一致警告）。

### 0.5.2 身份消歧：建立"身份指纹"，不是找学术 ID

**"先锁人（学术 ID）"不成立**——ORCID/OpenAlex/S2 本身有合并/拆分错误；且资历网页通常不展示学术 ID，无法把名单条目直接连到 ID。正确做法：

> **身份指纹** = 至少两个相互独立的强特征交叉确认：姓名及变体（中/英/缩写/拼音）、当前及历史机构、院系、研究方向、代表作、合作者、邮箱域名、个人主页、ORCID。

- 学术 ID 只是指纹的一部分，**不是真值**；锁的 ID 若被污染（OpenAlex 合并错误），比不锁更糟
- **锁不上怎么办**（新学者/无英文发表/纯中文圈）：降级为"单位+姓名+研究方向"三元组，结论置信度上限锁死在 `likely`（见 0.5.5）
- **同名高灾区**（Wei Wang / Lei Zhang / Jian Yang 级）：强制要求机构证据
- 锁人证据必须**带进结论**：报告要能回答"你查的 X 凭什么就是目标 X"（单位 + 时间窗 + 合作者 ≥2 项吻合）

### 0.5.3 声明—发布主体匹配（替代全局来源排序）

**"官方名录 > 单位官网 > 活动官网 > 个人页"的全局排序是错的**——来源可靠性必须**相对具体声明**判断：谁对该事实负有直接管理/发布责任，谁就是主来源。

| 声明 | 主来源（责任主体） |
|---|---|
| IEEE Fellow | 授予组织（IEEE）的名录/公告 |
| 当前职称/任职 | 当前雇佣机构的正式目录/任命信息 |
| 期刊编委/主编 | 期刊或出版方的编委页 |
| 当届会议主席 | 对应年份的会议组织委员会页面 |
| 学位/教育经历 | 授予机构记录；无法取得时用本人 CV/机构 profile（标记 self-reported）|
| 历史任职起止时间 | 同期任命公告、历史 CV、网页存档（Wayback Machine）|

**"官方名录(A) > 单位官网(B)"只在同一声明内成立**，跨声明不适用（例：查期刊编委，学校主页未必比期刊官网及时；IEEE 名录不能证明当前职称）。

**新闻的分级**（不是整体"不推荐"）：机构正式任命公告/学会公告/出版方公告 = **直接证据**；媒体采访 = 本人自述证据；转载/自媒体/无署名 = 仅检索线索。

### 0.5.4 时间语义：每条结论必须有时间边界

"教授""系主任""编委""会议主席"都可能**有有效期**。当前网页只能证明"查询时页面如此呈现"，不能自动证明过去或未来。

- 每条结果必须区分：**现任**（`valid_from`~至今）/ **曾任**（有 `valid_to`）/ **当届角色**（某年某届）/ **截至查询日仍在列**
- 禁止无时间限定地写"是编委/主席"——必须写"2026 年在任"或"2018 年任 KDD PC Chair"
- **历史态查询**：当年会议官网/旧编委页会下线 → 用 **Internet Archive Wayback Machine**（历史态查询首选工具）
- **A 类（院士/Fellow/杰青）把"当选年份"列为名录的标准字段**，年份查不到才允许降级；"现在不在名录"≠"从未获得"（头衔可能被撤销/除名——区分"历史获得 vs 现持有"）

### 0.5.5 证据规程：确认门槛、独立性与置信度

**"交叉验证"必须有定义**（否则两个转载同一份简历的网页被误当"双源验证"）：

- **独立源** = 非互相转载、非同一自述源头（CV 与 LinkedIn 是**同一源头**——都是本人自述，不构成交叉）
- **证据充分性**（替代固定"双源"规则）：一级直接证据（授予方名录/任命公告）可单独确认；次级证据（高校新闻、机构页）需独立来源补强
- **自述不是最高证据**：本人 CV/个人主页可能与事实冲突（夸大/过期/虚构），**矛盾时回 A/B 类权威源裁决；裁决不了 → 降级 `unverified` 并记录矛盾点，不得默认采信自述**

**结论状态（四值，替代"确认/疑似/存疑"的模糊三分）**：

```
confirmed            = 责任主体直接证据 + 独立佐证一致（A 类须在官方名录）
likely               = 1 个责任主体源，或 2 个非权威独立源；锁人证据不足时上限
not_found_after_search = 触发终止条件后仍无（≠ 不存在！）
indeterminate        = 证据矛盾/无法裁决/源不可及
```

**"未获取"≠"不存在"**：搜索失败可能因姓名变体、网页下线、搜索引擎未收录、登录限制、名单不公开。只有**封闭、完整、覆盖目标年份的官方名录**才支持有限否定判断（"未出现在该组织截至某年的公开名录中"），仍不宜直接写"不是"。

**置信度拆四维**（不能只输出一个没解释的"高"）：身份匹配 × 来源权威性 × 声明直接性 × 时间适用性，最终等级由规则合成并附降级原因。

**角色受控词表**：保留网页原文 + 归一化角色，**禁止向上推断**——`Associate Editor` 不得归一化为 `Editor-in-Chief`，`PC Member` 不得写成 `Program Chair`，中文"教授"要区分正/副/特聘/荣誉（`raw_title` + `normalized_role` 两字段）。

### 0.5.6 搜索 query 构造（组合规则，不是固定字符串）

**query 生成 = 组合规则**：`身份变体 × 机构变体 × 角色同义词 × 年份/届次 × 站点限定`。每个角色词**单独查询**（`|` OR 语法在部分搜索引擎不可移植，中文引擎对引号精确匹配支持差，拆成多个独立 query）：

```
# 基础组合（中文）
"<中文名>" "<单位>" "<角色词>"          # 角色词按类型换：院士|杰青|IEEE Fellow|编委|主席
# 基础组合（英文）
"<English Name>" "<University>" <role>
# 站点限定——必须用域名清单，不能裸用 site:edu.cn（会漏中科院系）
site:edu.cn OR site:cas.cn OR site:ac.cn "<中文名>" "<角色词>"   # 中国机构
site:ieee.org "<Name>" fellow / site:acm.org "<Name>" fellow     # 学会官方
site:elsevier.com "<Name>" editor / site:<期刊域名> "<Name>"     # 期刊方
# 历史态
"<Name>" "<Role>" 2018 chair / "<会议名>" 2018 program committee
# 履历类（换关键词覆盖"海外经历"等新问题）
"<中文名>" 海外|留学|访问学者|博士后|工作经历 / "<Name>" education|career|postdoc
```

**名字变体规则**：中文名、拼音全名、缩写（J. Yang / Jian Yang / Yang Jian）、复姓/变音符号、简繁体都要试；不强行把外文职级映射为中国职级（如需映射单列 `normalized_rank` 并标注依据）。

**终止条件（防无限搜索，必设预算）**：
```
≥3 个 query 变体 × ≥2 个搜索后端，或累计搜索 ≥8 次仍无权威源
→ 判 not_found_after_search，并记录已尝试的 query 清单（可审计、可复跑）
```

### 0.5.7 产出 schema（每条资历结论的固定字段）

没有 schema，批任务产出无法审计、对比、发现系统性错误。每条结论至少：

```yaml
subject:
  canonical_name:        # 规范姓名
  identity_evidence:     # 锁人证据（单位/时间窗/合作者 ≥2 项）
  academic_ids:          # ORCID / OpenAlex / S2（如有）

claim:
  category:              # 职称|Fellow|编委|会议主席|海外经历|教育背景|...
  raw_title:             # 网页原文称谓（保留）
  normalized_role:       # 归一化角色（受控词表，禁止向上推断）
  organization:          # 机构/期刊/会议
  edition_or_year:       # 届次/年份（如 2018, KDD）
  valid_from: / valid_to: # 时间边界（缺则标"截至查询日"）
  status:                # confirmed|likely|not_found_after_search|indeterminate

evidence:
  url:                   # 来源 URL
  publisher:             # 发布主体（决定证据类型）
  evidence_type:         # direct|self_reported|secondary|inferred
  observed_at:           # 查询日期
  archived_url:          # Wayback 存档（历史态必填）
  independent:           # 是否与其它来源互相转载（False 则不算独立验证）

assessment:
  identity_match:        # high|medium|low
  source_authority:      # high|medium|low
  claim_directness:      # high|medium|low
  temporal_fit:          # high|medium|low
  overall_confidence:    # 由四维规则合成
  caveat:                # 降级原因/矛盾点
```

### 0.5.8 信息类型速查（声明 → 主来源 → 证据类型）

| 类别 | 主来源（责任主体）| 证据类型 | 统一名录？ |
|---|---|---|---|
| 院士/Fellow（A1 终身制）| 授予组织名录（带当选年）| direct | ✅ 封闭可枚举（可机读性各异，见下）|
| 人才计划/基金（A2 聘期制）| 主管部门/基金委 | direct | ⚠️ 部分（长江无统一库；杰青 2024 起不公开）|
| 奖项（A3）| 授奖组织官网 | direct | 逐项注明名录质量 |
| 职称/任职（B）| 当前雇佣机构正式目录/任命 | direct | ❌ 无统一库 |
| 期刊编委/主编（C）| 期刊/出版方编委页 | direct | ❌ 无聚合 |
| 会议主席（C）| 当年会议官网 Committees | direct | ❌ 一年一换 |
| 海外经历/教育背景（D）| 授予机构记录；否则 CV（self-reported）| direct/self-reported | ❌ 非结构化 |
| 历史任职/编委/会议角色 | Wayback Machine + 同期公告 | direct（存档）| ❌ |

**可机读性陷阱**（官方名录存在 ≠ 能抓到）：IEEE Fellows Directory 需 JS 渲染；基金委历年名单散见 PDF/扫描图；院士名单页结构常改版。降级链：**官方名录不可机读 → 搜索引擎索引的官方页面快照 → 机构授衔新闻**。保存证据：URL + 页面标题 + 抓取时间 + 关键原文 + 存档链接（动态页标"当前页面快照"）。

## 2. 交叉验证方法（核心）

**为什么必须交叉**：单一来源可能是同名误配、名单抄错、过期信息。交叉验证 = 两个以上**独立来源**互相印证。

### 2.1 证据强度分级

| 级别 | 证据 | 示例 |
|---|---|---|
| **强证据** | 官方名录直接命中 + 独立佐证一致 | 中科院院士馆命中 + 高校官网"院士"介绍页一致 |
| **强证据** | 论文致谢 NSFC 资助号 ↔ 基金委系统项目号 | "Grant No. 62xxxxxx" 与系统项目对上 |
| **中证据** | 单官方源命中 | 仅院士馆一条 |
| **弱证据** | 第三方汇总/媒体喜报 | 青塔/时代学者/公众号（需二次核实）|

### 2.2 交叉维度（至少取 2 个）

1. **官方源 × 第三方**：院士馆 ↔ 高校官网师资页（两者独立维护）
2. **官方源 × 高校新闻**：教育部长江学者名单 ↔ 学校官宣喜报（时间、姓名、单位对照）
3. **头衔年份 × 论文时间线**：院士当选年 ↔ 该年后的代表作/合作变化吻合
4. **头衔单位 × 论文署名单位**：杰青归属单位 ↔ OpenAlex 上作者最新机构一致
5. **资助号 × 基金委系统**（杰青/优青专属）：论文致谢基金号 ↔ 系统项目详情

### 2.3 同名防误配（必须先做）

```
同一姓名（如 "Wang Wei"）可能对应多个人：
1. 用 OpenAlex/S2 作者 ID 锁人（机构/方向/代表作比对）
2. 头衔查询必须带"单位"（如 "杰青 王晓伟 北京大学"）
3. 两个不同单位的同名者 → 分别核验，绝不混用
```

### 2.4 结论标注规则（四值状态，与 §0.5.5 一致）

| 情况 | 标注 |
|---|---|
| 责任主体直接证据 + ≥1 个独立佐证 | **confirmed**（附来源链；A 类须在官方名录）|
| 仅单责任主体源 / 锁人证据不足 | **likely**（注明缺口）|
| 触发终止条件（§0.5.6）仍无权威源 | **not_found_after_search**（记录已试 query；≠ 不存在）|
| 证据矛盾 / 源不可及 / 自述与权威源冲突无法裁决 | **indeterminate**（记录矛盾点）|

> 旧版"确认/疑似/存疑/无法验证"四词已弃用——"疑似/存疑"缺乏操作定义，且"无法验证"混淆了"不存在"与"未获取"。
